# 展示站維持繁中單語，退場英文 TL;DR 與雙語敘事切換

## Context

Showcase Site 最初的 PRD（issue #5，user story 4 / 9 / 10）與其子任務 #8（雙語專案敘事 EN／中切換）、
#9（最新天英文 TL;DR）假設讀者含**不讀中文的英語招募方**，因此要求首頁提供英文 TL;DR 與中英切換。

實際運作後兩點改變了這個前提：

1. **用途回歸個人自用**：站台主要是自己看與存檔，不再以「說服陌生英語招募方」為主要目標。
2. **英文的邊際成本高、邊際價值低**：每日多一段英文 TL;DR 要多一次 27b LLM 生成，明顯拉長 pipeline
   輸出時間；而現代瀏覽器與外掛的網頁即時翻譯已足以覆蓋偶爾的英語讀者需求，系統自產英文的必要性大幅下降。

線上實況也已與此一致：`gh-pages` 首頁的「今日重點」為繁中、「關於本專案」敘事僅繁中、無 EN／中 切換——
**實作早已是繁中單語，反倒是 PRD 文件仍在承諾英文**，形成願景與現實的落差。本 ADR 把決策對齊到現實。

## Decision

**Showcase Site 維持繁體中文單語**，正式退場英文 TL;DR 與雙語敘事切換。

- 首頁最新天不再輸出英文 TL;DR；「今日重點」即為繁中導讀。
- 專案敘事只保留繁中版，不提供語言切換。
- 面向偶發英語讀者的需求，交由瀏覽器內建／外掛的網頁翻譯處理，系統不自產英文。

本決策 **supersede** PRD #5 的 user story 4、9、10 中「英文 TL;DR／雙語切換」部分，並將 #8、#9 的
產出視為已退場（其餘 Showcase Site 目標——公開展示、歷史存檔、系統狀態區——不受影響，仍然有效）。

## Considered Options

- **維持雙語（英文 TL;DR + EN／中切換）** — 否決：個人自用前提下，英文層的維護與每日 LLM 生成成本
  換不到相稱價值；且線上早已未呈現，維持只是讓文件繼續說謊。
- **改為系統自產「英文全文翻譯」** — 否決：成本更高、與「無聊技術／輸出時間」原則相悖；瀏覽器翻譯已夠。
- **保留英文 TL;DR 程式碼但預設關閉** — 否決：留著未接線的產出路徑是熵；要退場就從敘事與文件一併退場。

## Consequences

- PRD #5 的英語招募方相關 user story（4／9／10）不再是有效需求；未來讀 PRD 者以本 ADR 為準。
- 若日後重新面向英語受眾，需另立 ADR 復活英文層，而非默默改回。
- 若程式碼中仍殘留英文 TL;DR 的生成路徑（`TldrStep` 等），屬可清理的死碼；本 ADR 只記錄決策，清理與否另議。
